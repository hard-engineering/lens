# Implementation Notes

Status of the build, deviations from spec v3.1, and verification gaps.

## Environment in which this was authored

The code in this branch was authored in a Linux container with no access to
Xcode, the iOS Simulator, or any Apple toolchain. Consequences:

- The Swift sources have **not been compiled**. Any Swift-only compile error
  (typo, generic-inference quirk, deprecation that turned into a hard error in
  the user's Xcode version) will surface on first build.
- The Xcode project file was hand-authored, not generated by Xcode. It targets
  Xcode 15+ (`objectVersion = 56`, `compatibilityVersion = "Xcode 14.0"`).
- **§10 acceptance criteria and §11 visual verification protocol were not run.**
  Both require Mac + Xcode + Simulator.

Anything claimed to "work" below is by code inspection only — not measured.

## Deviations from spec

- **B&W filter implementation.** Spec §7 suggests Metal compute shader or vImage.
  This implementation uses a CoreImage chain (`CIBoxBlur`, `CIDivideBlendMode`,
  `CIMultiplyCompositing`, `CIColorKernel` for the Sauvola comparison). CIKernel
  source is the legacy CIKernel Language (not Metal), which avoids any
  `.ci.metal` build-system setup. On Apple-Silicon devices CoreImage compiles
  to Metal automatically. The 500ms/2400px target should hold on iPhone 13+;
  **measure on-device before relying on it**.

- **Sauvola constant R.** Spec gives R≈128 for an 8-bit space. The CIColorKernel
  operates in normalized 0..1, so R is set to 0.5 (half the dynamic range).
  k = 0.34 as per spec.

- **Shadow normalization scaling.** Implemented via `CIDivideBlendMode` (output
  = base/blend, clamped at 1.0). No separate gain step to a 235 target white
  point as the spec suggests — division naturally lands near 1.0 (≈255) for
  page background. Visually inspect the §11 `bw_output.jpg` to confirm; tune if
  output is dim.

- **Page limit (50).** Enforced as a post-capture warning in the Review screen
  rather than blocking capture (matching spec §4 note).

- **PDF text layer.** Uses `PDFAnnotation(type: .freeText)` with clear color
  + 1pt font, per spec §9. Spotlight and PDF search will see these; this is the
  same approach Apple's PDF samples use. Real text extraction (`PDFDocument.string`)
  collects annotations into the document string only on iOS 14+; verify by
  parsing the produced PDF in `§10` step 6 — annotation text **does** appear
  in `PDFDocument.string` based on Apple sample behavior, but not all PDF
  consumers will index it. If a third-party PDF reader fails to search, switch
  to drawing the OCR layer with a custom `CGContext`-based renderer that emits
  invisible text via `kCGTextDrawingModeInvisible`. Not done by default to keep
  the build dependency-free.

- **Corner editor loupe.** Implemented as a 140pt circular UIView that
  re-renders the source image at 2x scale around the touch point. Apple-style
  in spirit; not a literal copy of UIKit's text-selection loupe (which is
  private API).

- **VisionKit iOS 26 regressions** noted in spec §4 are not worked around —
  using stock `VNDocumentCameraViewController`. Custom AVFoundation capture
  remains deferred per spec.

## §11 visual verification — owner to run

I cannot drive the simulator from this environment. To complete the
self-inspection loop:

1. Provide real `shadow_doc.jpg` and `angled_doc.jpg` in `test_inputs/`
   (see `test_inputs/README.md` for guidance).
2. Boot a Simulator and run:
   `xcrun simctl addmedia booted test_inputs/shadow_doc.jpg test_inputs/angled_doc.jpg`
3. Use the in-app **Import from Photos** flow on each fixture; export with the
   B&W filter applied; save the rendered PDF page to disk.
4. Capture screenshots via:
   `xcrun simctl io booted screenshot test_outputs/screenshots/<step>.png`
5. Inspect against the pass criteria in spec §11.3.

If a future agent with simulator access continues this work, it should run
the loop and update this file in place.

## Known gaps

- **PHPicker permission alert.** PHPicker uses the system out-of-process picker
  that does not require `NSPhotoLibraryUsageDescription` and never triggers
  authorization-denied. The §10 #9 "Photos permission denial" criterion as
  written does not apply to PHPicker. The Info.plist still declares the key
  so if we ever move to PHPhotoLibrary direct access the path is in place.
- **Single recognition language (en-US)** per spec §8. Adding more languages is
  a one-line change to `OCRService` but out of scope.
- **No unit/UI tests** in the project. A `LensTests` target with PDF
  text-layer round-trip and filter-pixel-sampling assertions would directly
  satisfy §10 criteria 6 and 7. Out of scope for this pass.
- **Empty `UILaunchScreen` dict** produces a blank black/white screen at launch
  rather than a styled splash. Spec calls for "placeholder" — acceptable.
